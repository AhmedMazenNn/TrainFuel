# Milestone 5 validation

Implemented on isolated `feature/milestone-5`, based on Milestone 2; no main/dev merge or publication is performed by the milestone agent. Development database `trainfuel_milestone5` and PostgreSQL test database `test_trainfuel_milestone5` are separate from other terminals. Browser ports: API18005/web15175.

- Nine PostgreSQL progress tests pass: actual five-thread photo allocation accepts four; failed move retains old photo; replacement/deletion preserves/reuses slot and queues original/thumbnail cleanup; cross-owner/catalog-admin privacy; weight active date uniqueness, idempotent replay and stale-deletion protection; reminder validation; lifecycle export/scrubbing; direct PostgreSQL Monday/weekday/revision checks.
- Combined existing accounts/config/sync/media plus progress regression run passed 46 tests before the final additional direct-constraint test. The final nine progress tests also pass after all three migrations. Fresh test database migrations and local forward migrations work; `check` and migration drift checks pass.
- Progress browser checks exercise desktop Chromium and Pixel7: durable offline weight and staged photos after restart/reconnect, Arabic RTL/narrow overflow, photos/comparison without weights/zoom, reminder persistence, opt-in private-photo cache and clearing, recoverable fifth-photo reassignment, denied notification permission. The complete account/offline/progress regression run passed **24/24 browser tests**, including all 12 progress scenarios.
- Frontend TypeScript and production build pass. Postman JSON has ten documented requests; its manual photo attachment needs a ready asset from M2's upload collection. A Postman/Newman execution is not claimed here.

An actual photo-cache race was fixed: writes now atomically recheck account, opt-in and cache epoch, so a late download cannot undo clear/logout. A rapid-save auto-sync race was fixed by using operation keys actually considered during replay for follow-up work scheduling. These shared foundation changes must be preserved during integration.

Limitations: JPEG/PNG/WebP progress images supported; HEIF/animation remain recoverable but unsupported. Private storage is local development with the inherited S3 option, not live S3 verification. Browser reminders are best effort while open/visible (service-worker notification display where available); closed-browser guarantees/native/email/SMS are excluded. Snapshot/history browser retention still uses the foundation's whole-account snapshot; paginated REST reads are available, and large production histories need snapshot scalability validation. Release backup retention/offline disconnected-device erasure remain lifecycle requirements rather than instant erasure claims.
